# MCP-RES review checklist

A reviewer records the exact requirement/profile version and compares the change with its pre-fix behavior. A merge is ready only when every applicable item is evidenced or explicitly `NOT_APPLICABLE` with a reason.

- Normative source and immutable reference are pinned; roadmap or proposal text is labeled non-normative.
- Required fields and changed semantics advance the appropriate version and include migration behavior.
- A positive case, intended reason-bound rejection, wrong-reason mutant, stale-expected-failure control, and stable diagnostic execute.
- Observation reachability, artifact integrity, scenario/run identity, required coverage surfaces, and cleanup are bound.
- JavaScript/Python decisions, diagnostics, canonical bytes, and digests agree on shared inputs.
- Input is inert and bounded; no submitted path, URL, plugin, archive, code, or subject is resolved or executed.
- Performance and field claims name workload, environment, sample, evidence class, and limitations.
- Integrity, authenticity, producer trust, reliability, protocol conformance, and security certification remain distinct.
- Credentials, raw authorization data, private paths, personal data, and unverifiable adoption claims are absent.
- Profile registry, gap ledger, documentation, source-drift pins, and release bundle are updated.
- `mcp-res-v*` cannot trigger npm publication; all required checks pass on the exact head.
- Conflicts of interest and implementation/vendor interests are disclosed.

Security-sensitive reports use the repository's [private reporting path](../../../SECURITY.md), not a public issue.
