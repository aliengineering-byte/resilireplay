# Naming decision

Observed `2026-08-27`. Exact searches covered GitHub repositories, code, and issues; npm; PyPI; crates.io; RubyGems; the public web; IETF Datatracker; W3C; and OASIS. Searches used both `MCP-RES` and the full phrase `MCP Reliability Evidence Standard`.

No exact material collision was found. Exact package lookups for `mcp-res` returned `404` from npm, PyPI, crates.io, and RubyGems. GitHub and web searches returned unrelated substring matches such as “MCP REST” or isolated uses of “res”; none named a reliability-evidence specification. The IETF, W3C, and OASIS searches returned no standard with this name.

Decision: retain **MCP Reliability Evidence Standard (MCP-RES)**. The name is always accompanied near first use by the disclaimer that it is project-defined, independent of the official MCP specification, and not a certification or endorsement. A future material standards collision would require an RFC and migration aliases rather than an unrecorded rename.
